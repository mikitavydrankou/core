# App Architecture Rules

Этот документ фиксирует правила структуры и развития backend, чтобы проект оставался удобным при росте.

## 1. Структура каталогов

```text
app/
  main.py
  core/
  modules/
    root/
      router.py
    dispatch/
      router.py
      service.py
      templates/
    monitor/
      router.py
      service.py
      templates/
    simulator/
      router.py
      templates/
    realtime/
      router.py
  shared/
    message_store.py
```

## 2. Принцип организации

- Используем feature-first: код группируется по бизнес-модулям, а не по типам файлов.
- Каждый модуль хранит свой HTTP/API вход и свою прикладную логику рядом.
- Общий код выносим в shared только если он нужен минимум двум модулям.

## 3. Правила слоев

- router.py содержит только транспортный слой (маршруты, парсинг запроса, возврат ответа).
- service.py содержит прикладную логику и оркестрацию.
- shared содержит переиспользуемые компоненты без привязки к конкретному модулю.
- core предназначен для инфраструктурных настроек (config, logging, exceptions) по мере роста.

## 4. Правила импортов

- В main.py подключаем только router каждого модуля.
- router.py может импортировать service.py своего модуля и shared.
- service.py не должен импортировать router.py.
- Избегаем циклических зависимостей между модулями.

## 5. Правила шаблонов

- HTML-шаблоны храним внутри своего модуля: modules/<feature>/templates/.
- Путь к шаблону формируем от текущего файла модуля, а не от глобального каталога.

## 6. Правила добавления новой фичи

1. Создать каталог modules/<feature>/.
2. Добавить минимум router.py.
3. Если появляется логика, добавить service.py.
4. Если есть UI, добавить templates/.
5. Подключить router в main.py.
6. Добавить тесты для нового API/поведения.

## 7. Правила обратной совместимости

- Старые пакеты routers и services сохранены как shim-слой для совместимости импортов.
- Новый код пишем только в modules и shared.
- Удалять shim-слой можно только после полной миграции внешних импортов.

## 8. Definition of Done для изменений структуры

- Проект запускается через docker compose без ручных правок.
- Все основные страницы доступны: /sim, /dispatch, /monitor.
- WebSocket /ws продолжает принимать сообщения и отдавать ack.
- Документация обновлена при любом изменении структуры.
